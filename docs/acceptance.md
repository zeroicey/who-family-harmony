# 鸿蒙版对齐验收标准

> 验收对象：`hcyj-harmony` 当前代码。
> 参考实现：`../who_family_wechat`（微信小程序，只读）。
> 验收 agent **只读源代码**，不修复任何问题；发现问题写入报告并退回编码 agent。

## 0. 验收原则

1. **以参考实现源码为准**，不以"看起来差不多"为准。每个页面先读小程序对应 `.vue` 与其子组件，再逐项核对鸿蒙页面。
2. **功能优先于像素**：核心链路必须可用；视觉要求结构、配色、层级、间距节奏一致，允许系统差异（状态栏、字体渲染）。
3. **允许偏差必须登记**，未登记即视为缺陷。
4. **验收可复现**：记录提交号、构建命令、设备/模拟器、后端环境、每一步操作。
5. **不修改代码**：验收 agent 只能写 `docs/acceptance-report.md` 与截图，不能改 `entry/`、`build-profile.json5` 等。

## 7. 缺陷分级与通过规则

| 级别 | 定义 | 示例 |
| --- | --- | --- |
| **Blocker** | 无法继续验收或核心不可用 | 构建失败、启动崩溃、白屏、核心接口全挂、密钥泄露、参考实现被改 |
| **Major** | 核心功能/页面缺失或严重不符 | 页面不存在、发布/下单/评论不可用、AI 完全无输出、大面积视觉错位、数据丢失 |
| **Minor** | 非核心差异 | 文案个别不一致、图标/间距偏差、次要空态文案、轻微动画差异 |

**通过规则：**

- Blocker = 0
- Major = 0
- Minor 全部登记（页面、描述、截图、建议），由项目负责人决定是否本轮修复。
- 未测项必须标记 `NOT TESTED` 并说明原因，不能算通过。

## 8. 允许偏差登记（预置）

| 偏差 | 原因 | 验收处理 |
| --- | --- | --- |
| 无登录页 / 无微信登录 | demo token 决策 | 不作为缺陷 |
| 无微信好友分享/朋友圈/订阅消息 | 平台能力差异 | 不作为缺陷；如用系统分享替代则验证可用性 |
| 无支付 | 产品未实现 | 不作为缺陷 |

| 无本地后端 cleartext 配置 | 本机网络环境限制 | 生产 HTTPS 下不构成缺陷；本地模式问题单独记录 |

新增偏差必须写入报告并经项目负责人确认，编码 agent 不能自行宣布"允许偏差"。

## 9. 证据与报告格式

### 9.1 截图

- 目录：`docs/acceptance/screenshots/`
- 命名：`<page>-<state>.png`，例如 `community-list-default.png`、`community-publish-empty.png`
- 每个页面至少一张默认态；关键状态补充。
- 截图需能看到完整页面（含标题栏/底部 Tab），不要只截局部。

### 9.2 报告

输出 `docs/acceptance-report.md`，结构：

```markdown
# 验收报告

- 提交：<git sha>
- 日期：
- 设备/模拟器：
- 后端环境：
- 构建结果：
- CodeLinter：

## 全局门槛
| ID | 结果 | 证据/备注 |

## 页面结果
| 页面 | 结果 | 已验证项 | 缺陷编号 | 截图 |

## 缺陷清单
| 编号 | 级别 | 页面 | 描述 | 复现步骤 | 期望 | 截图 |

## 允许偏差
...

通过 / 不通过（Blocker x / Major y / Minor z）
```

### 9.3 复验

- 编码 agent 修复后，验收 agent 只复验缺陷项 + 受影响页面，不重复全量。
- 复验结论追加在同一报告末尾，记录新的提交号。

## 10. 验收流程

1. 确认代码冻结，记录提交号。
2. 执行构建与 CodeLinter，记录输出。
3. 安装到设备/模拟器，确认演示 token 生效。
4. 按第 4 节逐页走查，每页截图并记录结果。
5. 执行第 5、6 节异常与性能场景。
6. 对照参考实现源码，检查文案/区块/交互差异。
7. 汇总缺陷、分级、写入报告。
8. 给出通过/不通过结论；不通过则退回编码 agent，等待下一轮复验。
